## Пять приёмов, чтобы стол стал предметом (без новых токенов)

1. **Столешница как поверхность, а не карточка**: доска на `--panel-2`, без радиуса по бокам (на всю ширину 375, радиус только у нижнего края 16) — стол упирается в края экрана, как настоящая столешница, а пузыри остаются плавающими на `--bg`.
2. **Кости с одним ребром**: `box-shadow: 0 1px 0 --border` (1 px, без blur — «Движение» и «Поверхности» тени не запрещают, blur нет) + заливка `#d9cfc0`; рука — `#f0e7dc`. Две ступени бумаги = «лежит / в руке».
3. **Свет от лампы**: радиальный градиент `--panel-2` → `--panel` от верхнего центра доски, 0.06 амплитуды; в CSS — один `background`, токены те же. Даёт «светло над столом, темно по краям», убирает плоскость.
4. **Кости в руке чуть веером**: `rotate(-2deg / 0 / 2deg)` при статике (это не анимация, transform без transition) — рука становится рукой, а не второй строкой доски.
5. **Счёт как надпись мелом**: имена игроков — Golos `--muted`, числа — `--mono` `--fg` на верхней кромке доски слева/центр/справа; у ходящего — точка 6 px `--accent` перед именем (форма + цвет, 1.4.1). Убирает строку «ход: Аня» на A и освобождает 24 px.

## Три главных вывода

- 🔴 C2 несёт четыре акцентных носителя (рамка, «я здесь», таймер err, отправка); A и C — по два залитых. Причина одна: отправка залита при пустом поле. Один щелчок правила «залита только при вводе» приводит 4 кадра к норме и тот же дефект в 08.
- 🟡 Стол не отличается от беседы ничем, кроме прямоугольника с костями: шапка идентична 08, поверхности одной ступени. Доска на `--panel-2` во всю ширину + иконка домино в подзаголовке + две ступени бумаги для доски/руки — три правки, дающие «предмет».
- 🟡 Яркость перевёрнута: кости `#f0e7dc` — самое светлое на экране, при этом действие («ваш ход», кнопки) — тише. Приглушить доску до `#d9cfc0`, руку оставить, счёт — в mono `--fg` с точкой у ходящего.

## 4. Таймер хода 5:00 — 2.2.1 (`open.tsv:158`, открыт с 15.09)

Позиция: **исключение «essential» не тянет, но и продление не нужно — берём «настраиваемо» через уже существующее поведение**. Разбор:
- «Существенный» по 2.2.1 — когда без срока действие теряет смысл (аукцион, экзамен). Тут срок введён как защита от отсутствующего (`chat_RU.md:644–650`, «выбраны, а не измерены»), то есть это техническая мера, а не суть игры. Домино и шахматы за столом соседей без часов — валидная игра. Исключение не применимо.
- Из трёх допустимых путей (отключить / настроить / продлить): продление «нажми, чтобы получить ещё» — самый дешёвый, но за столом на чужой ход оно превращается в затягивание для остальных четверых. **Рекомендую:** срок хода — настройка стола при его создании (3 значения: 2 / 5 / 15 мин, как у беседы «четыре значения» в правиле :82), плюс автопас при истечении сохраняет партию (не потеря данных: пас, не проигрыш). Это закрывает 2.2.1 буквой «настроить не менее чем в 10 раз» — нет, 15/2 = 7.5×; если нужен строгий 10×, третье значение 20 мин. При этом 3 паса → зритель остаётся.
- Что записать: `open.tsv:158` закрыть решением «настройка стола, три значения, autopass — не потеря»; в `accessibility-and-i18n_RU.md:83` заменить «не решено» на это. Кадр H «отсчёт хода за замком» текст не задан — с настраиваемым сроком таймер за замком показывать словами («ваш ход, осталось 3 мин»).

Это 2.2.1 в чистом виде (не даёт способа продлить) и UX-баг. Сделать: при потере связи узел стоит на стороне узла, таймер — тоже; клиент не должен рисовать бегущий отсчёт, которого не видит узел; либо после реконнекта — одно продление на длину разрыва.

## 5. Диктор: объявление ходов / заявок / высадки (4.1.3 Status Messages)
