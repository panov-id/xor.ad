## Находки по существу

### Безопасность
1. Дефект — нет пределов частоты у close, alive, span, inbox, списков и снятий.
2. Дефект — `PATCH` срока оживляет беседу после своего срока.
3. Дефект — `/hidden` не проверяет право видеть фразу: заблокированный
   подтверждает id и читает текст через `GET /hidden`.
4. Противоречие — nonce не привязан к маршруту: протокол §2 требует 409 на
   тот же nonce с другого маршрута.
5. Мелочь — временной оракул у блокирующего (цена признана, SEC-1).
6. Мелочь — предел тратится до проверки повтора nonce.
   Без дефекта: порядок nonce, рост таблицы, IDOR, инбокс, обход блока лайком.

### Данные и СУБД
1. **Воспроизведено:** мэтч переживает блокировку — удалялся только при
   `chat_id IS NULL`; уборка беседы обнуляла `chat_id` по внешнему ключу, мэтч
   возвращался в инбокс как pending, и согласие открывало беседу поверх блока.
   То же без блока: закрытая беседа возвращала свой мэтч.
2. Гонка лайка и блока: блок не брал блокировку пары.
3. Порядок блокировок строк `chat_participants` в трёх местах — по скану.
4. Уборщик бесед: seq scan, без пачек, `NOTIFY` вне транзакции с UPDATE.
5. Лента: anti-join по `blocks` — 50 мс на 20 002 фразы и 1 239 блоков.
6. Лайки пары блок не трогает; `identity_stats.matches` не уменьшается.
   Без дефекта: дублей в инбоксе нет; `hidden` ON CONFLICT корректен.

### Согласованность и контракт
1. `POST /blocks`: контракт обещал 409 NonceReused, код отвечал 204.
2. `DELETE`/`PATCH /chats/{id}`: нет 404, 503, тел ответов.
3. 503 не описан у инбокса, билета, блоков, скрытого.
4. `POST /hidden`: 404 и 400 не описаны; `{line}` не принимается.
5. 429 объявлен, кодом не отдаётся у девяти маршрутов; `after`/`next` инбокса.
6. Снятие блока и возврат скрытого отвечают 204 при сбое базы.
7. Экран 7 обещает «закончилась» — `ended` был недостижим.
8. Протокол §4.3/§4.8 называл построенное «спека».
