## Находки по существу

### Безопасность
1. Дефект дизайна — эпоху решает узел: клиент не помнит, на какой эпохе опубликовал свою пару,
   и привязывает половину собеседника к эпохе из инбокса. Узел откатывает обе строки к эпохе 0
   с честно подписанными половинами согласия — клиент шифрует под ключ потерянного устройства.
2. Дефект дизайна — `acceptRekey` подписывает новую половину, не проверив просьбу: узел один
   подделывает «собеседник сменил устройство», рабочая пара выброшена.
3. Противоречие — спека велит спросить человека; `acceptRekey` и есть согласие, экран не построен,
   зовётся только из теста. Раскрыто в спеке.
4. Без дефекта — подделать перевыпуск без долгого ключа нельзя.
5. Мелочь — сторона может держать беседу «в перевыпуске» бесконечно; равно отказу говорить.
6. Мелочь — сторона, не звавшая перевыпуск, держит старую беседу в кэше и шифрует старыми ключами;
   `pending_deliveries` под старыми ключами не чистятся.
7. Без дефекта — порядок блокировок по identity.
8. Мелочь — мэтч, переоформившийся в тот же чат, не переносит новые половины согласия.
9. Мелочь — бюджет общий с сообщениями.
10. Без дефекта — `rekey_requested` считается верно.

### Контракт и данные
1. Дефект дизайна — DDL `chat_participants` в спеке без колонок db/036 и db/038.
2. Противоречие — «Схемное следствие» всё ещё говорит «места нет, надо завести» в 50 строках
