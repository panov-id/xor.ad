## Находки по существу

### Безопасность
1. Дефект дизайна — подпись над голым SPKI без домена и привязки: узел может перенести
   половину личности из мэтча A в мэтч B (DoS, не раскрытие); долгий ключ подписывает и строки
   запросов, и половины одними параметрами.
2. Дефект дизайна — повторное согласие с нового клиента: узел держит первую половину
   (`coalesce`), клиент верит в новую → все сообщения не открываются, без диагностики.
3. Противоречие — узел принимает согласие без половины, инбокс помечает чат «не шифруется»;
   §8.13 такого режима не знает. Клиент `depth` открытым текстом не шлёт никогда.
4. Мелочь/дизайн — AES-GCM без AAD; узел может повторить кадр внутри чата.
5. Мелочь — `fromBase64url` без проверки алфавита.
6. Мелочь — долгий ключ `depth` неизвлекаем, а §8.13 велит извлекаемый ради переноса.
7. Мелочь — `LEFT JOIN matches` при чате, пережившем мэтч, теряет половины для нового клиента.
   Без дефекта: ключи направления, HKDF по спеке, nonce, неизвлекаемость, обе проверки,
   раскрытие долгого ключа только участнику, мэтч при живом чате не удаляется, TOCTOU, 8 КБ.

### Протоколы и контракт
1. Дефект дизайна — контракт допускает нешифрованный чат (то же, что Без. 3).
2. Противоречие — у согласия нет `requestBody` в контракте, только проза.
3. Противоречие — 400 `invalid_body` не в ответах согласия.
4. Противоречие — DDL спеки без `ephemeral_signature`, UPDATE без `:sig`.
5. Противоречие — абзац «K один на двоих» жив рядом с решением о двух ключах.
6. Противоречие — «~1 КБ» в §8.13 против 1,4 КБ в §8.1 (1404 знака; в 2048 влезает с запасом 644).
7. Мелочь — недосказанное спекой: что подписывается, кодировка соли, форма на проводе, U+2192.
8. Мелочь — предел 256 знаков на половину не в реестре.
9. Мелочь — «не построено» для `chat_key_wraps` только в роадмапе, не в спеке.
10. RU/EN сходятся; протокол не датировал половину.
