## Сырые находки — по существу

### Безопасность

1. Дефект — приватная половина пары обёртки (ECDH) терялась сразу после
   регистрации: всё запечатанное на `wrap_pub` стало бы неоткрываемым.
2. Дефект — заглушки ПИНа и бумажного кода могли уехать как настоящие:
   личность без ПИНа и без восстановления.
3. Мелочь — приватный ключ подписи извлекаемый.
4. Мелочь — `x-protocol-version` и `content-type` вне подписи; вреда нет,
   нужна строка в §2.
5. Мелочь — один отрицательный контроль подписи из пяти возможных.
6. Мелочь — ответ не в JSON бросает исключение, статус теряется.
   Не нашёл: логирования ключей, записи на диск, утечки тестовых секретов.

### Протоколы и контракт

1. Ответ не в JSON (как Без. 6).
2. Нет `Retry-After` на 429/503 и различения двух форм 409.
3. `feed()` без курсора `after`.
4. Порядок и кодировщик в §2 не названы — «клиент и узел могут разойтись на
   не-ASCII и `!'()*`» (НЕ ПРОВЕРЕНО агентом).
5. Радиус не сужен до пяти значений контракта.
6. Контракт противоречит §6: у `POST /feed` нет 409.
7. `Profile` без `required`.

### Эксплуатация и стенд

Прогон агентом: 6/6, 8,9 с, ни контейнеров, ни сетей после выхода.
1. SIGKILL оставит контейнеры — метка и зачистка в начале.
2. `postgres:16-alpine` плавает.
3. Нет кэша Deno — каждый прогон качает зависимости.
4. Вывод миграций в `/dev/null`.
5. Живые тесты молча пропускаются без переменных — зелёный пустой прогон.

### Согласованность

1. Роадмап: «колонка клиента пуста везде» при `[~]` в трёх строках.
2. Шаг 2 клиента `[ ]`, а ядро умеет фразу и ленту.
3. Заглушек в коде три, в роадмапе две.
4. `depth-client_*` не говорит, что код есть и чего в нём нет.
5. README не упоминают `depth` — решение владельца, не дефект.
