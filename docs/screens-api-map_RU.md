# Экраны против контракта API

Сверка 19.09.2026: каждое данное на 14 листах макетов (`panel/design/sheets/`, 178 кадров)
против `docs/api/openapi.yaml` (105 операций: 39 построено, 66 описано) и `docs/protocol_RU.md`.
Цель — до кода найти всё, что экраны показывают или отправляют, а контракт не даёт.

**Как сделано.** Три агента-читателя (только чтение) разобрали листы: 01-08, 12-19 и
20-25 с i18n и светлым. Каждое данное отнесено к одному из классов: *есть* (операция и поле с
номером строки yaml), *частично* (операция есть, поле или состояние не описано), *дыра*
(нет ни операции, ни поля), *на устройстве* (по описанию экрана живёт только на устройстве).
Ведущий перепроверил каждую находку, помеченную здесь **ПРОВЕРЕНО**, по самому yaml,
протоколу и описаниям экранов в репозитории sosed.place. Пометка **НЕ ПРОВЕРЕНО** значит:
заявка агента, ведущим не сверена.

Контракт при сверке не менялся; `scripts/check-openapi.sh` зелёный.

## Дыры по темам

### Офферы — описаны 19.09.2026 (протокол §4.13, 17 операций `spec`)
Ниже — то, что было до этого.
**ПРОВЕРЕНО**: в yaml нет маршрутов `/offers`, `/o/`, полей `venue`, `discount`, `promo`;
`FeedItem.kind` — только `phrase` и `table` (`:197`). В `docs/offers/SPEC_RU.md` маршрутов тоже нет.
При этом оффер рисуют листы 03, 04, 06, 09, 17, 23, 25, а `GET /likes` сам пишет, что
отдаёт «офферы частников» (`:1254`). Недостаёт: карточки оффера в ленте (заведение или «частник»,
скидка, условия, срок, промокод, ссылка), всего кабинета заведения (вход, проверка точки
конвертом, форма, автопроверки, статистика, жалобы «скидку не дали», ответ модератору),
перехода `sosed.place/o/…` и жалобы «ссылка ведёт не туда».

### Лента
- `POST /feed` без тела запроса — текст, режим, зона, оффер не описаны. **ПРОВЕРЕНО** (`:1216-1231`).
- У `FeedItem` нет срока (`expires_at`) — ни «остаток», ни «скоро исчезнет». **ПРОВЕРЕНО**.
- Название места («Колонаки, Афины · примерно») не отдаёт ни одна операция — открытый вопрос 6 в `docs/api-platform_RU.md`. **ПРОВЕРЕНО**.
- `/feed/density` отвечает «Ступень.» без схемы и без порога «мало людей». **ПРОВЕРЕНО** (`:1277-1291`).
- У `GET /feed` параметров фильтров нет **по замыслу**: возраст и языки живут в профиле (`filter_age_min`, `filter_age_max`, `languages`, `:537-539`). Дыра уже: **фильтру режима** («компания») места нет ни в профиле, ни в запросе. **ПРОВЕРЕНО**.
- Нет пометки «дальше, чем вы просили», числа «ещё десятки на других языках», сигнала «фильтр сузился». **ПРОВЕРЕНО**: слов farther, other_lang, narrow в yaml нет.
- «Своя на проверке»: в ленте автора нет, а у `Profile.phrases` только `{id, expires_at}` — рисовать нечем, кроме копии на устройстве. **ПРОВЕРЕНО** (`:541-545`).

### Квота фраз
«свободно 2 из 4», «следующая в 21:40», «свободных мест 4 из четырёх» — полей нет.
**ПРОВЕРЕНО**: слова `quota`, `slots` в yaml есть только у ключей API панели.

### Входящие, мэтчи, беседы
- `GET /inbox` отдаёт `Page`, у которой `items: {type: object}` — ни имени и возраста, ни чужой фразы, ни срока, ни «ждёт вашего ответа». **ПРОВЕРЕНО** (`:255-263`, `:1350`).
- Отказаться от мэтча («не сейчас») и вернуть отказ нельзя: `decline` есть только в ответе на игровое предложение. **ПРОВЕРЕНО** (`:346`).
- Нет чтения одного мэтча, ответа «предложения больше нет», срока беседы, тела `PATCH /chats/{id}`, очереди реплик до согласия; системные строки беседы (`chat_opened`, ход, смена возраста, `peer_stepped_away`) описаны только в протоколе. **ПРОВЕРЕНО**: мэтч — только `/matches/{id}/consent` (`:1448`) с ответами 200, 400, 409, 429; `expires_at` в схемах есть только у партии; у `PATCH /chats/{id}` нет тела; `chat_opened` и `age_changed` в yaml не встречаются; очереди реплик до согласия нет ни в yaml, ни в протоколе.

### Личность, ПИН, перенос
- Старое устройство не может ответить «это я» / «не совпадает»: у сессий только `invite` и `claim`. **ПРОВЕРЕНО** (`:1098`, `:1163`).
- Нет тела у `POST /identities` (имя, возраст) и отказа «младше 13»; при создании не регистрируются ПИН, доля узла, бумажный код; нет поля «осталось попыток» и кода «заперто»; у `/recovery/claim` нет тела; новое устройство не может завести свой ПИН. **ПРОВЕРЕНО**: `POST /identities` — «ключ, имя и возраст», тело «не расписано в каноне»; в перечне `ApiError.code` из возрастных только `age_step_down`, кода «заперто» нет; попытки — только прозой (`:1218`); у `/recovery/claim` нет тела; `PinChange` требует прежний `current_auth`.

### Поддержка и документы
- В списке обращений нечем показать текст обращения: у `SupportRequest` нет поля текста. **ПРОВЕРЕНО** (`:396-403`).
- Нет `maxLength` 1000 у текста, даты прочтения ответа; у `/legal/manifest` и `/legal/accept` нет схем; «была 27.08.2026» нигде нет. **ПРОВЕРЕНО**: у `SupportCreate.body` нет `maxLength`, полей `seen_at`/`read_at` нет, у `/legal/*` нет схем, в `LegalReacceptance` нет прежней даты.

### Столы и игры
- Места за столом без имён: `TableLine`, `Board` знают номер места, а экраны пишут «Аня · 3», «ход: Аня». **ПРОВЕРЕНО** (`:308-316`).
- Нет состояния «партия окончена», извещения «вас попросили встать», числа фишек у соперников, роли по местам. **ПРОВЕРЕНО с оговоркой**: у `Board.state` тип `object` (jsonb по классу игры), так что «партия окончена» и число фишек могут жить внутри — это «не описано», а не «нет»; извещения исключённому в описании `/tables/{id}/kick` нет (`:1787`).

### Оформление и умолчания
- `PUT /identities/appearance` без тела и без чтения обратно, а экран 22 хранит выбор на узле. **ПРОВЕРЕНО**: у `PUT` нет тела, `GET` нет.
- Зона, режим и срок молчания по умолчанию не лежат в `Profile` — возможно, намеренно на устройстве; нигде не сказано. **ПРОВЕРЕНО**: слов default, silence в yaml нет.
