## Сырые находки

По существу как вернули агенты: уровни, ссылки и сценарии сохранены,
сокращены связки.

### Безопасность

1. Дефект дизайна — блокировку видно по `like_count`: `feed.ts` не фильтрует
   `blocks`; лайк заблокированного отвечает `liked`, а число на фразе не
   растёт (`feed.ts:331,398`, `likes.ts:111-120`, `openapi.yaml:219`). Правка:
   фильтр блокировок в ленте.
2. Мелочь — разница по времени: несуществующая фраза отвечает до блокировок,
   запрещённая проходит их и пустой INSERT (`likes.ts:75-78` против `90-121`).
3. Дефект дизайна — нет предела частоты; цикл POST/DELETE держит строку
   `identity_stats` автора под блокировкой.
4. Мелочь — `spent` считает истёкший мэтч (`likes.ts:236-237`).
5. Противоречие мелкое — отличимо только «это оффер», признак публичный.
   Не нашёл: обхода авторизации, утечки `rejected` через мэтч, подделки мэтча,
   IDOR, инъекций, двойного счёта.

### Данные и СУБД

Гонка встречных лайков воспроизведена двумя psql-сессиями в одноразовом
postgres:16: с блокировкой пары вторая транзакция ждёт и видит лайк первой —
мэтч рождается. Без блокировки двойной промах не пойман (окна не
перекрылись) — НЕ ВОСПРОИЗВЕДЕНО.

1. Средний — нет уборки истёкших `matches`; `spent` на любую строку пары.
2. Средний — `match_participants.message_id` без внешнего ключа.
3. Низкий — `matches.chat_id` без ключа (признанное отступление).
4. Низкий — `ON CONFLICT … SET id = EXCLUDED.id` меняет PK строки, на
   которую ссылаются участники; безопасно лишь потому, что предыдущий DELETE
   чистит их тем же `now()`.
5. Низкий — при закрытии личности `likes` уходят каскадом, `like_count` чужих
   фраз не уменьшается; `greatest(…,0)` маскирует рассинхрон.
6. Низкий — если строки `identity_stats` нет, `FOR UPDATE` молча ничего не
   блокирует.
7. Низкий — нет индекса `match_participants(message_id)` на будущее.
   Сверено без расхождений: полоса SQL против `band()`, `ON CONFLICT` на PK,
   `expires_at = least(...)`.

### Протоколы и контракт

1. Средняя — 503 не описан ни у POST, ни у DELETE.
2. Средняя — 429 обещан, ограничителя нет.
3. Средняя — таблицы протокола отстают: статус «спека», сломанная строка
   DELETE, нет `unliked` и `refused`.
4. Средняя — лайк на оффер снимается, спека говорит «не снимается».
5. Низкая — отступление `NOT EXISTS chats` не названо в контракте.
6. Низкая — `unliked` не заведено в спеке §8.4.
7. Низкая — карта тестов не называет `unliked`, `spent`, `refused`, 503.

### Эксплуатация

1. Дефект — нет предела частоты; пул из 4 соединений стоит за лайками.
2. Дефект — исчерпание пула при ожидании блокировок; предложен `lock_timeout`.
3. Дефект — истёкшие мэтчи никто не удаляет; `identity_sweeper.ts:83-84`
   всё ещё говорит «tables do not exist yet».
4. Дефект — `relay_like_total`/`relay_unlike_total` нигде не видны: ни панели,
   ни тревоги.
5. Внимание — `String(error)` в журнале может нести uuid из `DETAIL` Postgres.
   Проверено без дефекта: выкат 030 при старом узле безопасен, кардинальность
   меток, путь 503, регистрация, таймауты.

### Согласованность

1. Дефект — лайк на оффер снимается против экранов 5 и 25 обеих витрин.
2. Дефект — `spent` по паре, а экран 25 говорит «по фразе»; истёкший мэтч
   держит снятие навсегда.
3. Устаревшая строка сводки роадмапа «3–4 без таблиц».
4. Устаревшая запись `identity.cascades` в `open.tsv`.
   Сходится: отказ без своей фразы и экран 5, `unliked` в контракте, нет

## Сводка ведущего — закрыто тем же заходом

- Лента и плотность фильтруют блокировки в обе стороны (§8.9); тест красный
  до правки, контроль — без фильтра в плотности красный.
- Снятие лайка: оффер → `spent`; учитываются только живые мэтчи.
- Контракт: 503 у обоих методов. Протокол RU/EN: `refused`, `unliked`,
  `spent` у оффера, починена сломанная строка DELETE. Спека §8.4 RU/EN:
  `unliked` и «только живые мэтчи». Роадмап и `open.tsv` приведены.
- `030`: комментарий, почему `message_id` без внешнего ключа, и что уборки
  мэтчей пока нет.

Попутно: первая версия фильтра ленты ушла в SQL как `$$15` — ошибка моего
генератора правки. `query()` превратил синтаксическую ошибку в пустую ленту,
1248 строк журнала и ни одного внятного падения теста; нашлось по журналу.
