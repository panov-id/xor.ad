## 2. Продукт

- [ ] 2.1. `advertiser` (почта, вход) и `venue` (название, адрес, `verification_status`) —
      **две сущности**. Верификация принадлежит заведению: один владелец, несколько точек,
      каждая со своим конвертом
- [ ] 2.2. `offer` — **только заведения**: `venue_id`, обязательный `discount_value`,
      отдельное поле `conditions`, опциональные `promo_code` и `external_url`,
      `post_valid_hours`. Оффер частника отдельной таблицы не имеет: это `feed_messages`
      с непустым `discount_value` (`../chat_RU.md` §8.3)
- [ ] 2.3. Ссылки разрешены **только** в офферах и **только** бизнесу — проверка на уровне
      модели, не UI. Форма частника этих полей не показывает, но узел всё равно отклоняет
      запрос с ними мимо интерфейса
- [ ] 2.3a. Лимит `PRIVATE_ACTIVE_OFFERS` на личность — проверяется узлом
- [ ] 2.3b. У оффера бизнеса **нет лайка и нет пути в чат**: вместо лайка «Сохранить» в
      локальный список на устройстве. На сервере не появляется ничего
- [ ] 2.3c. Лайк на фразе со скидкой создаёт мэтч **сразу**, без встречного лайка;
      `match_participants.message_id` и `text_snapshot` становятся nullable у того, кто пришёл
      на оффер. Проверяется лайком с личности, у которой нет ни одной своей фразы
- [ ] 2.4. **Квота офферов в ленте** — не более 1 на N обычных постов, системная,
      считает офферы заведений и фразы со скидкой **вместе**
- [ ] 2.5. Лимит частоты офферов на бизнес
- [ ] 2.6. Кнопка **«Показать снова»**: форма, предзаполненная данными прошлого оффера,
      с возможностью правки. Никакого автоповтора и расписаний
- [ ] 2.7. Кнопка «скопировать промокод» + опционально список скопированного локально
      на устройстве, не на сервере
- [ ] 2.8. Ничего не строим: ни кодов погашения, ни квот на скидку, ни метрик для бизнеса

## 3. Верификация

- [ ] 3.1. Конверт: код активации со сроком 30 дней, адресат — владелец или управляющий
- [ ] 3.2. В тексте письма: активация создаёт обязательство давать заявленную скидку
- [ ] 3.3. В конверте наклейка и карточка для персонала — как подарок, без обязательств
- [ ] 3.4. Запасной путь: звонок на публичный телефон из открытого листинга
- [ ] 3.5. Кнопка «это не мы» для заведения → мгновенный `suspended`
- [ ] 3.6. При смене адреса верификация повторяется

## 4. Модерация и жалобы

- [ ] 4.1. Публикация немедленная и целиком для всех авторов, премодерации нет.
      Контроль — автопроверки, экран перехода, жалобы
- [ ] 4.2. Автопроверки при публикации: домен по репутационным спискам, **запрет сокращателей
      ссылок**, стоп-слова, дубли текста
- [ ] 4.2a. Экран перехода по внешней ссылке: полный домен, «мы её не проверяли»,
      кнопка жалобы на ссылку. Показывается всем и всегда
- [ ] 4.2b. Кнопка модератора «скрыть немедленно» — без ожидания трёх жалоб
- [ ] 4.3. Жалобы приватны: видят только модератор и бизнес. Публичных отзывов и рейтингов нет
- [ ] 4.4. Единственный предмет жалобы — объявленную скидку не дали. Сюда же обманувшее
      объявление: скидки не было, условия скрыты
- [ ] 4.4a. **Жалоба на качество услуги отклоняется с объяснением** — шаблон ответа
      называет причину, даёт контакт заведения из профиля и направление для
      потребительского спора. Молча не копим (`SPEC.md` §10, `../dsa/README_RU.md` §6)
- [ ] 4.4b. **Сообщить о незаконном контенте — отдельный путь** с карточки оффера,
      рядом с жалобой на скидку, ведёт в форму по ст. 16 (`../dsa/SPEC_RU.md` §2).
      Не путать с жалобой: другой предмет, другой разбор, обязательный ответ
- [ ] 4.5. Пожаловаться может любой, кто видел оффер
- [ ] 4.6. Лимит жалоб на пользователя в месяц, при превышении вес падает
- [ ] 4.7. Бизнесу видны текст и дата, без личности и без времени
- [ ] 4.8. Автоскрытие **оффера** (не профиля) при повторяющихся жалобах, разбор за сутки
- [ ] 4.9. Систематические жалобы после разбора → `suspended` **заведения**, а не учётной
      записи: одна точка набрала жалоб — остальные работают

## 5. Первые бизнесы

- [ ] 5.1. Выбрать 3–5 заведений с ежедневной проходимостью (кофейня, пекарня, барбершоп,
      студия йоги)
- [ ] 5.2. Обойти лично, код активации вручить в руки — почта это масштабируемый вариант,
      а не стартовый
- [ ] 5.3. Согласовать первый оффер: маленькая скидка (5–15%), никакой глубокой
- [ ] 5.4. Для студий и мероприятий — попросить их собственный промокод и ссылку
- [ ] 5.5. Честно сказать две вещи: метрик мы не даём (считайте по своему промокоду или
      спрашивайте на кассе) и повтор показа только руками — это цена бесплатности

## Чего не делаем

- Не берём деньги и не берём бартер
- Не делаем коды погашения и лимиты на количество скидок
- Не даём бизнесу метрики
- Не требуем фото наклейки — оно ничего не доказывает
- Не задаём минимальный размер скидки — это работа премодерации
- Не делаем автоповтор и расписания
- Не делаем публичные отзывы, рейтинги и звёзды
- Не делаем самообслуживаемый кабинет: первые бизнесы ведутся руками
- Не показываем заведению счётчик сохранений — это та же непроверяемая метрика
- Не даём частнику ссылку и промокод: тогда конверт перестанет что-либо значить
