# Ротация секретов

Ротация, которую ни разу не проводили, в нужный момент не проводится. Здесь —
что ротируем, чем и как часто. Документ короткий намеренно: длинный регламент
не выполняется.

## Что есть

| Секрет | Где живёт | Что случится при утечке |
|---|---|---|
| `ORIGIN_TOKEN` | правило края в Bunny + `caddy.env` на узлах | замок обходится: к узлу можно ходить мимо сети доставки |
| Ключи API витрин | в сборке витрины (публичные по назначению) + таблица `api_keys` | чужая витрина может слать заявки и жалобы от нашего имени |
| `GITHUB_TOKEN` | `deploy/.env.deploy` на машине разработчика | запуск раскаток, публикация релизов, доступ к трём репозиториям |
| `BUNNY_API_KEY` | там же | управление зонами, DNS, хранилищами |
| Ключ Resend | секреты узла | отправка писем от наших доменов |
| SSH-ключ `deploy-user` | машина разработчика | доступ к узлам пула |

## Как часто

- **Раз в год** — плановая ротация всего списка.
- **Немедленно** — при уходе устройства из-под контроля, при подозрении на
  утечку, при смене того, кто имеет доступ.
- `GITHUB_TOKEN` и `BUNNY_API_KEY` лежат открытым текстом на диске: это
  осознанный размен ради простоты раскатки, и он же причина, по которой
  срок для них короче — **раз в полгода**.

## Как

Каждый секрет ротируется **с перекрытием**: сначала новый начинает работать,
потом старый отзывается. Иначе ротация означает простой.

1. `ORIGIN_TOKEN` — добавить новый в `caddy.env` вторым допустимым значением,
   переключить правило края, убедиться, что трафик идёт, убрать старый.
2. Ключи API витрин — выпустить новый в `api_keys`, выкатить витрину, старый
   пометить отозванным через сутки.
3. `GITHUB_TOKEN` — выпустить новый с тем же набором прав, заменить в
   `.env.deploy`, отозвать старый в интерфейсе GitHub.
4. `BUNNY_API_KEY` — заменить в `.env.deploy`, проверить любым читающим
   скриптом из `deploy/`, отозвать старый.
5. Resend и SSH — по инструкции поставщика; для SSH новый ключ добавляется в
   `authorized_keys` до удаления старого.

## Открыто

- Ротация не автоматизирована и не напоминает о себе: календарной записи или
  задачи в CI нет. Пока это ручная процедура, зависящая от памяти.
- Проверки «а этот секрет точно больше нигде не используется» нет — при
  отзыве полагаемся на список выше, который надо держать полным.
