# DSA: что построить

Порядок — от того, что закрывает обязанность прямо сейчас, к тому, что делает её
удобной. Обоснования — в [README_RU.md](./README_RU.md), механика — в
[SPEC_RU.md](./SPEC_RU.md). Английская версия: [CHECKLIST_EN.md](./CHECKLIST_EN.md).

- [x] Условия: раздел о том, как формируется лента и куда сообщать
- [x] Условия: офферы отдельным разделом, платформа не сторона договора
- [x] Условия и политика: канал уведомлений, мотивировки, сроки хранения

- [x] Координатор цифровых услуг Кипра установлен и назван в условиях
- [x] Статус микропредприятия проверен и записан — README §3, проверка 05.08.2026

## До запуска — обязательно

- [ ] **Форма `report.html`** на обеих витринах: поля из SPEC §3, отдельный путь
      без имени и почты для случая §5.1
- [ ] **Подтверждение получения** — письмо через Resend, немедленно, автоматически
- [ ] **Таблицы `notice` и `statement_of_reasons`** с RLS: заявитель видит только
      своё уведомление, автор — только свою мотивировку
- [ ] **Слепок при создании уведомления** — до разбора, иначе контент исчезнет
      по таймеру раньше
- [ ] **Экран разбора в панели**: очередь, слепок, решение, отправка обоих писем
- [ ] **Удаление через год** — заданием по расписанию, вместе с существующей
      уборкой жалоб на офферы
- [ ] **Языки точки контакта (ст. 11(3))** — назвать в условиях языки, на которых
      с нами можно общаться. Среди них обязан быть официальный язык страны
      учреждения: для Кипра это **греческий** или турецкий. Сейчас языки не
      названы вовсе. Требует решения: обязуемся ли принимать обращения на
      греческом и как их обрабатываем
- [ ] **Ссылка на форму** в футере и на юридических страницах обеих витрин —
      механизм обязан быть «лёгким в доступе» (ст. 16(1))
- [ ] **Шаблоны писем**: подтверждение получения, ответ заявителю, мотивировка
      автору, отказ по жалобе на качество услуги. Каждый — с обязательными
      элементами из SPEC §6 и §7
- [ ] **Уведомление о существенных изменениях** документов. Условия и политика
      сами обещают «signposted in the Service», ст. 14(6) требует того же.
      Механизма нет: нужен баннер или экран при первом входе после правки

## После запуска

- [ ] Пункт «пожаловаться» в скрытом меню сообщения ведёт в форму с подставленным
      местом — сейчас там жалоба-голос, это разные вещи
- [ ] Тот же пункт на карточке оффера, рядом с жалобой на скидку
- [ ] Показ мотивировки в приложении, когда почты автора нет (SPEC §7)
- [ ] Формулировки причин отказа — общий список с механикой ленты

## Проверять регулярно

- [ ] Статус микропредприятия — **до 05.08.2027**, дальше ежегодно. Утрата
      включает Раздел 3 через год; запись обновлять в README §3
- [ ] Не появился ли у витрин оборот: платная реклама или подписка меняют и
      налоговую картину, и часть ответов в README

## Чего не делаем намеренно

Список с обоснованиями — в [SPEC_RU.md](./SPEC_RU.md), §10. Коротко: внутреннее
обжалование, внесудебное урегулирование, база решений Еврокомиссии, доверенные
заявители, публичная статистика.
