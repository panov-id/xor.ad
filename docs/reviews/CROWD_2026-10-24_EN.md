## Findings

1. **Nobody can sit at another's table (app defect).** The table shows in Tables, «Watch» opens the table screen with
   "Something went wrong. Try again.". The node answers 404 to `GET /tables/<id>` and `POST /tables/<id>/ticket`: by
   SEC-4 a table exists only for a seated person (`relay/node/src/routes/tables.ts:7`). The web seats the person
   before opening (`web/src/App.tsx:363`, `Tables.sit`); the app does not: `app/src/shell/App.tsx:246` `toTable` only
   switches the screen. 7 of 7 tries, every device. Shot: `shots/01-Boris-08-table-sit.png`.
   **Fixed** (24.10, on /go): `app/src/screens/tables/Table.tsx` sits first (`Tables.sit`), then reads the table and
   connects the room. Run 10: table 7 of 7, 82 of 90 in all. Break (the old file from a copy): table 0 of 7.
2. **A talk does not open, the field is off.** After «Let's talk» the chat stays "opening": `GET /chats/<id>/keys` →
   404 `no_wrap` (`relay/node/src/routes/chats.ts:469`), the field and quick replies disabled
   (`app/src/screens/Chat.tsx:120`). Shot: `shots/01-Boris-06-talk.png`. Run 10, both sides online and the field
   awaited for 60 s: keys never came for 3 of 10 (Boris, Hana, Elena). By the code the tab holds the key pair only in
   memory (`depth/web-platform/chat/keys.ts:122`); without it and without a wrap on the node the way out is a key
   reissue. The web shows the reason and a reissue button (`web/src/screens/Chat.tsx:122-124`), the app does not: the
   person sees a disabled field with no words (app defect). Run 11's journal: everyone whose talk failed had a reload
   before it (the waiting screen has no tabs, so the app was opened again) — the pair left with the tab. A live person
   who closes the tab while waiting ends up the same.
   **Partly fixed** (24.10, on /go): `app/src/screens/Chat.tsx` shows the reason and a «New keys» button (and the
   other side's request and the wait for their answer), as the web. Run 12: 6 of 6 such talks with the reason on
   screen; break (the old file): 6 of 6 without it. A talk after a reload still does not open without a reissue.
3. **Client errors never reach the panel.** Client errors is empty after a run whose consoles logged hundreds: neither
   `app/src` nor `web/src` catches `error` or `unhandledrejection`, and nothing is sent to the node.
4. **The panel calls `GET /admin/brands` for a moderator and gets 403** on Client errors and Page views. Not visible
   on screen (the brand picker is empty); an error in the console.
5. **Sign-ups from one address: 10 an hour, 30 a day** (`relay/node/src/lib/rate_limit.ts:145-146`). Ten neighbours on
   one Wi-Fi hit the limit. The run passes it the way the edge does in prod: `x-client-ip` under the stand's
   `x-origin-token`.

Not defects: 0 in Page views (page views come only with a site key, `relay/node/src/lib/api_key.ts:220`); «No access»
for a moderator on server logs, keys and brands.

docker bridges). The crowd's browser now lives in the `xor-local-app` container's network; such errors: 0.
