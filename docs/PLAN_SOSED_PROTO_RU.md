### В2. Страницы «Я» вместе с узлом
1. Карта проекта: `scripts/project-map.py` по `screens/me/*` и маршрутам узла `profile`, `statements`, `blocks`, `hidden`, `transfer`, `identity`, `away`. Цель: каждая плитка прототипа связана с маршрутом. Проверка: таблица «плитка → экран → маршрут» без пустых клеток.
   **Итог 26.10:** имя и возраст → EditName → `PATCH /identities/me`; фильтр → AgeFilter → тот же; скрытые → Hidden → `GET/DELETE /hidden`; заблокированные → Blocked → `GET/DELETE /blocks`; сброс → Reset → `POST /identities/close`; отойти → StepAway → `POST /away`; документы → Statements → `GET /statements`; тема, язык, место, QR — без узла. Пустая клетка одна — баннер ограничения. Заодно найдена живая ошибка: `Me.tsx` при каждом открытии зовёт `client.statements()`, и решения записываются доставленными. Решение: поле `restricted` в `GET /identities/me` через `EXISTS` без записи, а `Me.tsx` больше не зовёт `statements()`.
2. Экраны на разметке прототипа и `kit.css`: `Me.tsx` разводящий; `MeProfile`, `MeVisibility`, `MeSecurity` — новые; баннер `me-restrict`, если в `statements` есть действующее ограничение. Пути `/me/profile`, `/me/visibility`, `/me/security` в `router.ts`.
3. Код узла: только там, где карта покажет пустую клетку. Заранее известный кандидат — признак «есть действующее ограничение»: баннер не должен тянуть весь список. Требования линзы безопасности: (а) признак читает `EXISTS` без UPDATE, тест узла проверяет, что `delivered_at` после вызова остаётся NULL (`statements.ts:111-116` отмечает доставку всему, что отдал); (б) условие баннера (слово владельца 26.10, вопросник): только `access_restricted`, у которого `until` пуст или ещё не прошёл, тест по всем 4 видам из `dsa.ts:149`; (в) `allowSteppedAway: true` и проверка в `run-relay-tests.sh` с отошедшей сессией; (г) набор ключей ответа фиксирован тестом, данных заявителя нет. Опасные плитки me-security: сброс требует полный ПИН и `aria-disabled` до готовности, неверный ПИН показывает остаток попыток, анимация не переносит фокус на опасную кнопку.
