### Линза «Безопасность»

1. **Дефект дизайна / противоречие — начало фразы уходит через курсор `next`, а с ним и
   конец (§8.11).** `relay/node/src/routes/feed.ts:338-339` (`visible_at_cursor` в
   микросекундах), `feed.ts:439` (`next`), `lib/feed_verdict.ts:25,141` (срок фиксирован

   чем прежний `created_at`. Активно: `after` проверяется только по форме
   (`feed.ts:274-277`) — бисекцией по `(visible_at, id) < (after)` находится visible_at
   любой видимой фразы, ~40 запросов до микросекунды при `feed.read.hour` = 300. Коммит
   c04996e сам пишет «the cursor is untouched». Исправление — решение владельца:
   непрозрачный подписанный/шифрованный курсор; курсор только по id без подписи бисекцию
   не закрывает. НЕ ПРОВЕРЕНО живым прогоном.
2. **Мелочь — `/v1/waitlist` читает тело и ходит в БД до квоты** (`v1.ts:132-150`):
   исчерпанный ключ с новым `Idempotency-Key` теперь каждый раз читает тело целиком и делает
   один SELECT; потолка на размер тела в `relay/node/src` нет. Поадресный лимитер
   (`v1.ts:61`) по-прежнему первым.
3. **Мелочь — depth верит `Retry-After` без верхней границы** (`depth/ink/rooms.ts:1007`,
   `depth/core/client.ts:130-134`): `retry-after: 1e300` даёт «через 2.8e+296 ч».
- Проверено, чисто: `checkAll` в два прохода (проба в контейнере: отказ не списывает

  ключу `/v1` отдаёт только свой сохранённый ответ (ячейка `brand:key:sha256(body)`);

### Линза «Данные и эксплуатация»

1. **Дефект дизайна — отлучка, кончившаяся по сроку, не будит комнату** (`relay.ts:81-86`,

   на момент `until` или минутная выборка кончившихся отлучек с тем же `pg_notify`.

   выдачи после отлучки оставит накопленное лежать.
4. **Мелочь — два запроса и гонка между `away()` и `pendingFor`** (`relay.ts:77`, `:60-61`):
   уход в миллисекундах между ними — строка не отдана, `held` не поднят.
